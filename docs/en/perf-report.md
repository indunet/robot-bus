# robot-bus performance report

Generated by `just perf` (`cargo run --release --bin robot_bus_perf`).

## Environment

- robot-bus: 0.1.8
- Logical CPUs: 24

## Method

- In-process `RobotBusBroker` with `bind_all_transports = true` (tcp + ipc + inproc + grpc).
- Console HTTP off; message HWM=2048 (bench only); service/action HWM=64.
- Payload: 64-byte raw (first 8 bytes = sender Unix nanoseconds for latency).
- Message **throughput (primary)**: paced send for ~1.0s (or fixed count via `ROBOT_BUS_PERF_GOODPUT_TRIAL_MSGS`); **binary search** for max sustainable rate (max goodput) with loss ≤ 1.0% and pub/sub ≥90% of the target rate in the send window.
- Message **latency**: separate paced sample of 5000 (send one, wait for receive).
- Service / action: 10000 / 5000 iters (`ROBOT_BUS_PERF_SVC_ITERS` / `ROBOT_BUS_PERF_ACT_ITERS`); latency timed per call / send_goal.
- ZMQ: shared `Context` + `Node::tcp` / `ipc` / `inproc`; gRPC: `Node::ws_at`.
- inproc and the embedded broker must share one `Context` (ZeroMQ inproc is context-local).
- Numbers are single-host loopback and machine-dependent; not CI gates.
