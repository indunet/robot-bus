# Robot Bus 性能测试报告

2026-11-20 单机复测覆盖 TCP、IPC、inproc、WebSocket 和双 broker 邦联。每个场景测三轮。此次采样使用 Robot Bus 2.4.0、Rust 1.100.0、ZeroMQ 4.3.4 和 Release 构建，源码以提交 `b9b414e` 为基线，包含归档中的 benchmark 修订。两套测试的硬件和容器配置见[性能说明](performance.md)。

本页 Topic 测的是 Robot Bus 原始 64 B 字节路径。与 ROS 2 对齐应用层编码后的 Topic 结果见[预编码 CDR 对照](performance.md#预编码-cdr-topic-对照)。

## 方法

- 消息负载 64 B，单发布者、单订阅者，本机进程内编排。原生队列 HWM 为 2048，WS Subscribe 的服务端队列深度为 2048。WS Publish 测 WebSocket 进入原生订阅端，WS Subscribe 测原生发布端进入 WebSocket，邦联测 Broker A 到 Broker B。
- 每档发送 1 秒，排空 100 ms，从 100 到 750,000 Hz 按 100 Hz 步长搜索。通过一档要求排空后丢失率不超过 1%，且发送窗口内收、发速率均达到目标速率的 90%。各路径所选档位均低于搜索上限。
- 消息单向延迟另采 500 条，每次收到后再发下一条。Service 和 Action 各预热 8 次后串行执行 32 次。Action 包含一条反馈及最终结果。32 个样本的 RPC p99 对单个慢样本敏感。

## 计数和 Action 延迟排查

- 历史 WS Subscribe 曾记录 100.1% 投递率。旧计数器在切换试验时清零，前一轮排队的消息仍可进入后一轮。历史日志缺少逐条标识。新测试按轮次和序号计数。在受控回归中，当轮发送计数为 1，共观察到 3 个到达事件，其中同轮唯一消息、跨轮消息和重复消息各 1 条。正式复测的 77 个 WS 吞吐试验均满足同轮唯一接收数不超过发送数。
- TCP、IPC、inproc 的 Action 已用默认 SDK 路径复测。回复入队后会唤醒 executor，不再等待 250 ms 的 poll 超时。三轮中位 p50 为 TCP 542 µs、IPC 296 µs、inproc 126 µs。复测把进程绑到 CPU 32–39，预热和采样次数与表中其余行相同，但跑在宿主机上，没有原来的 8 GiB 容器内存限制。三轮日志在 `bench-results/20261120-2115-executor-wake/`。WebSocket 和邦联 Action 不经过这段等待，同一次复测仍约为 44 ms 和 0.34 ms，这两行保留原测量。

复现命令、每轮日志和原始数据的归档位置见[性能说明](performance.md)。
